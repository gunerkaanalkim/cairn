# Cairn DataTable — Onüçüncü ve Ondördüncü Adım: Yayın Öncesi Test ve Yayın

Onikinci adım tamamlandı. Kapsam adı `@gunerkaanalkim/cairn-datatable` olarak düzeltilmiş, yirmi altı testin yirmi altısı geçiyor, derleme temiz, demo sitesi yayında.

Planın onüçüncü adımı, paketi bir tarball hâline getirip tamamen ayrı bir projede denemeyi istiyor. Bu testi bulut ortamında senin adına çalıştırdım. Paket kuruldu, tipler çözüldü, çalışma zamanı doğru sonuç verdi. Ancak iki sorun çıktı ve ikisi de yayından önce kapatılmalı.

Çalışma alanı kökü: `cairn-workspace/`

---

## Yapılan test ve sonuçları

Sıra şuydu: `npm run build:lib`, sonra `dist/cairn-datatable` klasöründe `npm pack`, sonra tamamen ayrı bir klasörde sadece Angular bağımlılıkları olan boş bir proje, sonra üretilen tarball dosyasının oraya kurulması.

Geçen kontroller:

1. Paket sorunsuz kuruldu, altı paket eklendi, güvenlik uyarısı yok.
2. `npm ls tslib` çıktısı `tslib` paketinin sadece `@angular/core` ve `@angular/common` üzerinden geldiğini gösteriyor. Kütüphane kendi başına hiçbir bağımlılık getirmiyor, `strip-tslib.mjs` betiği işini yapmış.
3. Ana giriş ve `core` girişi, `bundler` ve `node16` modül çözünürlüğüyle sorunsuz çözülüyor.
4. Tip tamamlaması çalışıyor. `ColumnDef`, `TableApi`, `CairnClassNames` tipleri ve `cairnCell` şablon bağlamı doğru tiplerle geliyor.
5. Bileşen, `classNames`, `selectable`, `caption` girdileri ve özel hücre şablonuyla birlikte katı (strict) kipte derleniyor, tek uyarı yok.
6. Stil dosyası `node_modules/@gunerkaanalkim/cairn-datatable/styles/cairn-datatable.css` yolunda erişilebilir durumda.
7. Çalışma zamanı testi doğru sonuç verdi. `createTable` çağrıldı, sıralama uygulandı, satırlar beklenen sırada döndü.

## Görev 1 — Lisans dosyaları boş

Bu maddenin önceliği en yüksek. Hukuki bir eksiklik, teknik bir hata değil.

Gözlenen durum: hem `LICENSE` (çalışma alanı kökü) hem `projects/cairn-datatable/LICENSE` dosyası on iki bayt. İçlerinde tek bir satır var: `MIT License`. İzin metni yok, telif satırı yok, garanti reddi yok.

Bu hâliyle paket npm üzerinde MIT lisanslı görünür, ama gerçekte hiçbir kullanım izni vermiyor. Kurumsal bir kullanıcının hukuk taraması bu paketi reddeder, çünkü lisans metni geçersiz. Gerçek MIT metni yaklaşık bin yetmiş bayttır.

Düzenlenecek dosyalar:

1. `LICENSE` (çalışma alanı kökündeki)
2. `projects/cairn-datatable/LICENSE`

Yapılacak: her iki dosyaya standart MIT lisans metnini tam olarak yaz. Telif satırı şu biçimde olacak:

```
Copyright (c) 2026 Guner Kaan Alkim
```

İki dosyanın içeriği birebir aynı olsun. Metni kısaltma, sadeleştirme veya yeniden yazma. Standart MIT metninin resmi kaynağı: https://opensource.org/license/mit

Doğrulama: `wc -c LICENSE projects/cairn-datatable/LICENSE` komutu her iki dosya için bin baytın üzerinde bir değer dönmeli.

## Görev 2 — `core/package.json` dosyası pakete girmiyor

Gözlenen durum: `npm pack` çıktısındaki dosya listesi on dosya içeriyor ve `core/package.json` bunların arasında yok. Oysa dosya `dist/cairn-datatable/core/package.json` yolunda üretiliyor.

Sebep: npm, kendi içinde `package.json` taşıyan bir alt klasörü ayrı bir paket sınırı sayıyor ve o klasöre hiç inmiyor. İkincil giriş noktası tanımı bu yüzden dışarıda kalıyor.

Etkisi: modül çözünürlüğü `bundler` veya `node16` olan projeler etkilenmiyor, çünkü kök `package.json` içindeki `exports` haritası `./core` girişini zaten tanımlıyor. Angular yirmi bir ve üstü uygulamalar varsayılan olarak `bundler` kullanıyor. Ancak eski `node10` çözünürlüğüyle çalışan bir proje şu hatayı alıyor:

```
TS2307: Cannot find module '@gunerkaanalkim/cairn-datatable/core'
or its corresponding type declarations.
```

Bu paketin en önemli satış noktası iki katmanlı mimari. `core` girişinin bazı kurulumlarda çözülmemesi kabul edilemez.

Düzenlenecek dosya: `scripts/strip-tslib.mjs`

Yapılacak: betik zaten derleme sonrası `dist/cairn-datatable/package.json` dosyasını düzenliyor. Aynı yerde bir `files` alanı ekle. Bu alan varsa npm klasör atlama davranışını uygulamıyor ve listelenen her şeyi pakete koyuyor.

```javascript
// ng-packagr always injects a tslib dependency even when importHelpers is off.
// The emitted bundles contain zero tslib references, so the entry is removed here.
// The explicit files list also forces npm to include core/package.json, which npm
// otherwise skips because that directory carries its own package.json.
import { readFileSync, writeFileSync } from 'node:fs';

const path = 'dist/cairn-datatable/package.json';
const pkg = JSON.parse(readFileSync(path, 'utf8'));
delete pkg.dependencies;
pkg.files = ['core', 'fesm2022', 'styles', 'types', 'LICENSE', 'README.md'];
writeFileSync(path, JSON.stringify(pkg, null, 2) + '\n');
console.log('Patched', path);
```

Doğrulama: bu değişikliği denedim ve çalışıyor. Şu komut dizisi ile kontrol et:

```bash
npm run build:lib
cd dist/cairn-datatable && npm pack
tar tzf gunerkaanalkim-cairn-datatable-0.1.0.tgz | sort
```

Listede `package/core/package.json` satırı görünmeli, toplam on bir dosya olmalı. Ürettiğin tarball dosyasını sonra sil, depoya işleme.

## Görev 3 — Yayın öncesi son kontrol listesi

İlk iki görev bittikten sonra sırayla çalıştır.

1. `rm -rf dist .angular && npm run verify` — hatasız geçmeli, yirmi altı testin yirmi altısı geçmeli.
2. `npm run build:lib` — `dist/cairn-datatable/package.json` dosyasında `dependencies` alanı olmamalı, `files` alanı olmalı.
3. `cd dist/cairn-datatable && npm publish --dry-run` — çıktıdaki paket adı `@gunerkaanalkim/cairn-datatable`, sürüm `0.1.0` olmalı. Dosya listesinde on bir dosya olmalı: iki `fesm2022` demeti ve iki harita dosyası, iki tip dosyası, `core/package.json`, `styles/cairn-datatable.css`, `package.json`, `README.md` ve `LICENSE`. Beklemediğin bir dosya varsa dur.
4. `wc -c dist/cairn-datatable/LICENSE` — bin baytın üzerinde olmalı.
5. Kütüphane README dosyasını npm önizlemesiyle karşılaştır. Rozetler henüz paket yayınlanmadığı için "not found" gösterecektir, bu normaldir ve yayından sonra düzelir.

## Görev 4 — Ondördüncü adım: 0.1.0 sürümünü yayınla

Bu bölüm kod işi değil, senin elinle yapılacak. Gemini'ye devretme.

### Ön koşullar

1. npm hesabın açık ve e-postan doğrulanmış olmalı.
2. İki aşamalı doğrulama etkin olmalı.
3. `npm whoami` komutu `gunerkaanalkim` döndürmeli. Döndürmüyorsa `npm login` yap.
4. Yerel npm sürümün 11.5.1 veya üstü olmalı. Kontrol: `npm -v`. Değilse `npm install -g npm@latest`.

### İlk yayın

Güvenilir yayın (trusted publishing) ayarını henüz kuramıyorsan, ilk sürümü kendi makinenden elle çıkar. npm arayüzü henüz var olmayan bir paket için güvenilir yayın bölümünü göstermeyebilir.

1. `npm run build:lib`
2. `cd dist/cairn-datatable`
3. `npm publish --access public`

`--access public` bayrağı zorunlu. Kapsamlı paketler varsayılan olarak özel kabul edilir ve ücretli plan ister. İki aşamalı doğrulama kodu istenirse gir.

### Yayın sonrası doğrulama

1. `npm view @gunerkaanalkim/cairn-datatable` — sürüm, lisans ve bağımlılık alanlarını kontrol et. `dependencies` alanı görünmemeli.
2. https://www.npmjs.com/package/@gunerkaanalkim/cairn-datatable adresini aç. README'nin düzgün render edildiğini, kod bloklarının renklendiğini, lisansın MIT göründüğünü ve rozetlerin artık yüklendiğini doğrula.
3. Tamamen boş bir klasörde `npm install @gunerkaanalkim/cairn-datatable` çalıştır, kurulumun gerçekten çalıştığını gör.

### Sonraki sürümler için güvenilir yayını kur

İlk yayın tamamlandıktan sonra paket npm üzerinde var olur ve güvenilir yayın bölümü açılır.

1. Paket ayarlarında "Trusted Publisher" bölümünü aç, GitHub Actions'ı seç.
2. Kullanıcı adı `gunerkaanalkim`, depo `cairn`, iş akışı dosyası `publish.yml`. Ortam adı alanını boş bırak.
3. İzin verilen eylem olarak `npm publish` seç.
4. `.github/workflows/publish.yml` dosyasında `setup-node` adımından sonra bir satır ekle: `- run: npm install -g npm@latest`. Node yirmi iki ile gelen npm sürümü 10.9, güvenilir yayın ise 11.5.1 istiyor.
5. Aynı dosyada yayın adımından `env` bloğunu ve `NODE_AUTH_TOKEN` satırını sil. `--provenance` bayrağı da gereksizleşir, güvenilir yayında köken kanıtı kendiliğinden üretilir.
6. Bundan sonra `NPM_TOKEN` sırrına hiç ihtiyacın olmaz. Tanımladıysan depo ayarlarından sil.

### İlk sürümü etiketle

1. `git tag v0.1.0 && git push origin v0.1.0`
2. GitHub üzerinde bu etiketten bir sürüm (release) oluştur. `publish.yml` iş akışı `release: published` olayını dinlediği için, güvenilir yayın kurulduktan sonra ikinci sürümden itibaren yayın kendiliğinden çalışır.
